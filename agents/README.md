# Retail Ops Agent System

This directory contains the 5-component backend agent system for closed-loop demand forecasting and inventory allocation.

## Agent Architecture

1.  **Orchestrator (`orchestrator.js`)**: The state machine. It prevents agents from calling each other directly. It writes the JSON outputs directly into the Fabric Gold Delta tables (`gold_forecast`, `gold_agent_recommendations`, etc.) to persist the states.
2.  **Forecast Agent (`forecastAgent.js`)**: Stubs an async call to an external ML model (like XGBoost or LightGBM). Calculates baseline and adjusted demand based on external signals (e.g., weather). 
3.  **Allocation Agent (`allocationAgent.js`)**: Stubs a constrained optimization call (like OR-Tools) to determine the exact transfer quantity from a warehouse to a store while respecting inventory constraints.
4.  **Validation Agent (`validationAgent.js`)**: A purely deterministic, mathematical guardrail system. It checks the allocation plan against budget (< ₹5,00,000), capacity, safety stock, and confidence levels. If *any* check fails, the pipeline halts immediately.
5.  **Execution Agent (`executionAgent.js`)**: Operates on a strict Automation Matrix. For this implementation, we default it to Level 1 Human-in-the-Loop (Recommendation-only) where approval statuses are marked as `Pending Approval`.

## Dashboard Mapping

The JSON outputs generated by these agents are designed to perfectly match the UI properties in the React Dashboard:

- `ForecastAgent.adjusted_demand` ➔ maps to `forecast` in the `DemandRow` interface (Overview tab).
- `ForecastAgent.deviation` ➔ maps to the deviation percentage badge.
- `AllocationAgent.recommended_transfer_qty` ➔ maps to `expectedDemand` and `newForecast` logic in the Recommendation Cards.
- `ValidationAgent.checks` ➔ powers the "Guardrails & Automation" tab's matrix.
- `ExecutionAgent.transfer_order_id` ➔ mapped to the operational artifacts expected in the dashboard.
